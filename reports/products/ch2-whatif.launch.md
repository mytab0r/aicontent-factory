## Счётчик открытий по получателю
Получатель = YouTube-зритель US. Воронка и источник каждой цифры:
1. **Показы превью (impressions)** — только YouTube Reporting API, bulk-отчёт `channel_reach_basic_a1`, поле `video_thumbnail_impressions` (per video, per day); Analytics v2 targeted query на `videoThumbnailImpressions` отвечает 400 "query not supported" (проверено 23.10). Требует scope `yt-analytics.readonly` — добавлен в `youtube_oauth.SCOPES`, токен нужно перевыпустить. Скрипт `pipeline/ch2_snapshot.py` (reach-джоба идемпотентна, CSV последнего дня).
2. **CTR показов** — тот же отчёт, `video_thumbnail_impressions_ctr` (суточный срез).
3. **Просмотр (view)** — YouTube Data API `videos`/Analytics v2 `views` по видео (увидено в снапшоте и yt-dlp как прокси-проверка).
4. **Удержание 30 с / 50%** — Analytics v2 `averageViewPercentage` per video (метрика `metric()` в 08_post_analytics.py, переиспользована); порог «в разбор»: long < 30% avg, Short < 50% avg. Отдельной метрики «удержание на 30-й секунде» через API нет — прокси: среднее удержание + ранний отвал по кривой недоступны; принято как ограничение замера (в снапшоте фиксируется avg%).
5. **Подписка** — Analytics v2 `subscribersGained` per video (`metrics=subscribersGained, dimensions=video`).
6. **Источник трафика** — Analytics v2 `dimensions=insightTrafficSourceType` per video (SEARCH/RELATED_VIDEO/BROWSE/SHORTS_FEED...), суммарно views по источнику.
Снапшот: воркфлоу `ch2-snapshot.yml`, cron ежедневно 12:30 UTC + dispatch; вывод в лог шага и `reports/ch2_snapshot/<date>.md`.

## Премортем (прошлые инциденты и реальные риски — до публикации)
1. **Смешанная тема канала**: 3 формата в одной ленте + плейлист «Vending & Route Businesses» от ch1. Алгоритм не может определить аудиторию нового ролика → узкие показы. Фиксация: первые 2 недели list-ролики оцениваются по плейлисту, не по каналу. Разделение каналов вне скоупа (решение владельца).
2. **Нет кастомных обложек**: канал не верифицирован, `thumbnails.set` на канале без телефона-верификации даёт 403 — обложку выбрать нельзя, YouTube ставит автокадр. Риск: автокадр — случайная сцена. Смягчение: cover.png генерируется кодом (читаемая типографика) и ставится, если API позволяет; при 403 — фикс в снапшоте.
3. **Заголовок ≠ обложка**: автокадр/cover без текста не подтверждает заголовок → CTR падает. Смягчение: cover.png с крупным числом/словом пункта (код рисует), проверка: скриншот артефакта рендера.
4. **0 показов как ложный сигнал**: новый канал/плейлист может не получать показов днями. Решение: показы = дефект замера, если reach-отчёт пуст/нет строк по видео — «н/д», не 0. Kill-критерий активен только при impressions ≥ 1000.
5. **Детектор синтетики YouTube (10.2026)**: `containsSyntheticMedia: True` уже ставится (publish-код), озвучка edge-tts, стикмен = код-рисунок. Риск: ручная проверка «сделано ИИ» понижает охват. Смягчение: ротация голосов и мест между пунктами уже в коде; мониторинг impressions в снапшоте.
6. **TTS-голос без эмоций**: monotone-озвучка снижает удержание против конкурентного стикмен-контента (Chill Dude Explains — живой голос). Фиксация: avg retention в снапшоте, сравнение с референсом вручную. Апгрейд (вне скоупа): более выразительный TTS.
7. **Длина <8 мин без мидроллов**: What-if лонги короче 8 мин — мидроллы невозможны даже после монетизации; list-лонги 9.4–10 мин проходят порог 8 мин, но новичок-канал не монетизирован, так что это не блокер запуска. Реальный риск — удержание: 9.6–17.5% avg view на What-if лонгах (снапшот). Контроль: list-лонг < 8 мин отклоняет validate_script/test_listshow (хронометраж ≥ 9.5 мин).
8. **Дубли тем**: 15 тем TOPICS listshow ротируются; повтор одной темы чаще раза в 15 дней = усталость аудитории. Контроль: .state/listshow_idx.txt коммитится CI, проверка test_listshow.
9. **Авторские права на факты/картинки**: текст пунктов свой, изображения рисует код (стикмен, без чужих кадров), музыка нет (ролики без музыки, TTS). Источники фактов: общеизвестные факты без цитирования длинных фрагментов. Остаточный риск: совпадение формулировок с референсом — текст генерируется своей формулировкой.
10. **Часовой пояс публикации**: 16:30 UTC = 12:30 ET — US день, окно корректное; 18:00 UTC whatif = 14:00 ET. Проверка: cron-ы воркфлоу.
11. **Shorts без ссылки на long**: описание Shorts строится `descriptions(s, done.get("long"))` — «Full video: <url>» есть, только если long вышел раньше в том же прогоне; при сбое long Shorts уйдут без ссылки. Контроль: `listshow_channel.py verify` (сухой прогон) падает, если в описании Short нет URL long.
12. **Неверный плейлист**: ролик уходит в «Fascinating Lists» (listshow) или «What If...» (whatif) по `_playlist()`; вчерашний инцидент: list-ролики вышли без гейта в общий поток — плейлист верный, вопрос был не в нём.

## Kill-критерий
Выборка: ролики с **impressions ≥ 1000** и ≥ 100 просмотров; дедлайн решения — 14 дней с GO (не набрали выборку за 14 дней = NO-GO по охвату) (reach-отчёт, сумма по видео за 7 дней; impressions < 1000 и «н/д» = дефект замера, не сигнал — такие ролики в выборку не входят). Для 5 первых роликов, набравших ≥1000 показов: CTR < 2% при показах ≥ 1000 = заголовок/обложка убиты; CTR ≥ 2%, но avg retention < 20% (long) / < 35% (Shorts) = контент не удерживает; подписки < 1 на 1000 показов при живых двух предыдущих = канал не растёт. Любое из условий на всей выборке ≥ 5 роликов → ch2 в текущем виде убит: воркфлоу listshow/whatif возвращаются под флаг vars.LIST2D/CODE2D=0, карточка blocked с разбором. Ноль показов при пустом reach-отчёте = ДЕФЕКТ ЗАМЕРА, не результат: чинить замер, выборку не закрывать.
