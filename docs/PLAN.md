# PLAN — aicontent-factory

## Цель
Построить автономный, воспроизводимый конвейер генерации ИИ-контента
(музыка и/или faceless-видео) и публикации на одну платформу (YouTube —
приоритет, т.к. даёт AdSense + не требует дистрибьютора), с целью
долгосрочного пассивного дохода. Минимум ручного труда в steady-state
(целевая модель: человек раз в неделю смотрит отчёт и правит промпты/нишу).

Честные ожидания (зафиксировано в обсуждении с владельцем): это НЕ
нулевые усилия с первого дня. Монетизация реальна, но она про узкую нишу
с минимальной конкуренцией + воспроизводимый пайплайн + соответствие
правилам площадки (пометка синтетического контента), а не про "включил
и забыл". Первая итерация — MVP на одной нише, не распыляться.

## Итерация 0 — MVP (эту сделать первой, без неё дальше не идти)
Ниша: инструментальный lo-fi / ambient фоновый трек -> YouTube-видео
(статичная/медленно меняющаяся генеративная картинка + аудио), публикация
на отдельный YouTube-канал.

Почему эта ниша: минимальный объём контента на видео (не нужен сложный
монтаж/субтитры/сценарий), спрос стабильный (study/sleep/focus плейлисты),
можно сделать 100% пайплайн через 9router (image+LLM) без внешних платных
музыкальных API в первой версии — см. "Открытый вопрос: музыка" ниже.

### Шаги
1. `pipeline/01_idea.*` — через 9router (LLM chat) сгенерировать: тему/настроение
   трека, промпт для обложки, title/description/tags под YouTube SEO.
   Вход: ничего (ротация по списку настроений в `config/moods.yaml`).
   Выход: JSON с полями mood, cover_prompt, title, description, tags.
2. `pipeline/02_cover.*` — через 9router `/v1/images` (`model` из
   `/v1/models/image`, напр. `hf/black-forest-labs/FLUX.1-schnell` — бесплатнее/
   быстрее для старта) сгенерировать обложку по cover_prompt.
3. `pipeline/03_audio.*` — **открытый вопрос, см. ниже**. MVP вариант без
   внешних платных API: либо (a) процедурная генерация эмбиент-дорожки
   локально (напр. через готовую open-source библиотеку/простой
   синтезатор — проверить, что реально даёт приемлемое качество), либо
   (b) отложить этот шаг и для самого первого прогона взять 1-2 трека с
   лицензией CC0 как заглушку, чтобы проверить весь остальной конвейер
   end-to-end, музыку подключить отдельной задачей.
   Решение по (a) vs (b) — на усмотрение исполнителя по итогам короткого
   ресёрча (15-30 минут), записать выбор и причину в `docs/DECISIONS.md`.
4. `pipeline/04_assemble.*` — FFmpeg: статичная обложка + аудио -> mp4
   (зацикленный лёгкий Ken Burns/плавный зум, чтобы не было полностью
   статичного кадра — YouTube такое хуже ранжирует).
5. `pipeline/05_publish.*` — YouTube Data API v3 upload. Требует:
   - Google Cloud проект + OAuth2 credentials (client_id/secret) +
     refresh_token с правами `youtube.upload`.
   - **Это требует интерактивного OAuth-консента в браузере один раз** —
     если нет способа сделать это полностью автономно (нет доступа к
     браузеру пользователя), это тот самый "нужен секрет, которого нет
     нигде" — эскалировать в Telegram с чёткой инструкцией, что именно
     нужно от владельца (пройти OAuth-флоу по ссылке, прислать код).
     Не блокироваться на этом — остальной пайплайн разрабатывать и
     тестировать параллельно (dry-run без реальной публикации).
   - При загрузке выставлять поле `selfDeclaredMadeForKids` корректно и
     флаг синтетического контента там, где API это позволяет (см. актуальную
     YouTube API документацию на момент реализации — могло измениться).
6. `pipeline/06_report.*` — раз в N дней (cron) тянуть статистику через
   YouTube Analytics API, писать краткий отчёт в `docs/REPORTS/`, если
   настроен Telegram — слать агрегированную сводку раз в неделю, не чаще
   (не спамить).

### Оркестрация
- Cron внутри контейнера hermes или отдельный systemd timer на хосте,
  аналогично `pm-daily-audit.timer`. Частота публикации — начать с
  1 видео/день, не больше (риск спам-флагов на новом канале).
- Все шаги — простые скрипты (bash/python/go, что уместнее по месту),
  не городить n8n/Make для MVP — это лишняя инфраструктура, которую негде
  даже развернуть на 1 vCPU сервере с запасом. n8n можно рассмотреть ПОСЛЕ
  того, как ручной/скриптовый пайплайн доказал, что работает (YAGNI).

## Открытый вопрос: источник музыки
Suno/Udio не имеют официального публичного API (на момент постановки
задачи) и подключать их через неофициальные реверс-инжиненные обёртки —
риск (ToS, нестабильность). Перед тем как тратить на это время — проверить
актуальное состояние (может что-то изменилось). Если легального
автоматизируемого способа нет — не биться об стену, задокументировать
находку в `docs/DECISIONS.md` и идти по пути (a)/(b) из шага 3 выше.

## Критерии готовности MVP
- Запустить `pipeline/` end-to-end руками один раз -> получить готовый
  mp4-файл с обложкой+аудио+метаданными, лежащий локально (даже если
  публикация на YouTube ещё блокирована OAuth-секретом).
- Cron/timer настроен и реально срабатывает (видно в логах).
- `docs/DECISIONS.md` зафиксировал ключевые развилки и почему выбрано так.
- Статус отражён в kanban-задаче (комментарии по-русски).

## Явно НЕ делать в MVP (анти-скоуп)
- Не делать ИИ-инфлюенсера/лицо (сложнее, больше площадок-рисков).
- Не подключать несколько площадок одновременно (только YouTube сначала).
- Не строить admin-панель/дашборд — отчёт в виде markdown-файла достаточно.
- Не оптимизировать пайплайн под "вирусность" — сначала просто работающий
  воспроизводимый цикл с приемлемым качеством.
