# DECISIONS — aicontent-factory

## 1. Источник музыки (MVP, шаг 03)

Контекст: нужен инструментальный lo-fi/ambient трек под видео, без
платных внешних SaaS (п.2 AGENTS.md) и без риска по лицензиям.

Проверено:
- 9router (`/v1/models`) — **нет** ни одной рабочей музыкальной/audio-gen
  модели (есть только text-chat и image). TTS-эндпоинт `/v1/audio/speech`
  формально существует в API-поверхности роутера, но реальных
  провайдеров под музыку/генерацию звука за ним не подключено.
- Suno/Udio — официального публичного API нет (см. открытый вопрос в
  PLAN.md), неофициальные обёртки — риск ToS/нестабильность, решили не
  трогать для MVP.
- CC0-треки как заглушка (вариант b) — отложили: добавляет ручной шаг
  (поиск/лицензионная проверка каждого трека), не масштабируется без
  участия человека.

**Выбор: вариант (a) — процедурная генерация локально**, чистый
numpy + stdlib `wave` (pipeline/03_music.py):
- случайные lo-fi минорные септаккордовые прогрессии (детерминированно
  по сиду = имя run-директории, чтобы прогон был воспроизводим);
- мягкая огибающая на аккордах + лёгкий low-pass (собственный
  однополюсный RC-фильтр) + статический "винил"-шум для тёплого
  звучания;
- полностью бесплатно, без лицензионных рисков, работает оффлайн.

Важная находка по среде: `scipy.signal.butter/lfilter` подвешивает
процесс насмерть на этом 1-vCPU хосте (threadpool deadlock) — поэтому
в `pipeline/03_music.py` **намеренно нет scipy**, только numpy.

ponytail: это не "настоящая" музыка с мелодией/ударными, а эмбиент-подложка.
Апгрейд, когда появится бюджет/нужда в качестве: подключить внешний
music-gen API (Suno/Udio/ElevenLabs Music и т.п.) за тем же интерфейсом
`generate_track()` — остальной пайплайн не изменится.

## 2. Сборка видео (шаг 04) — вшивание текстовой пометки

`ffmpeg -vf drawtext=...` на каждый кадр оказался неприемлемо медленным
на 1 vCPU (~0.13x realtime, т.е. 120s трек кодировался бы ~15+ минут).
Решение: надпись "AI-generated / synthetic content" печатается ОДИН РАЗ
в саму PNG-обложку через Pillow (`burn_overlay()`), а не per-frame
фильтром. Для статичного кадра результат идентичен визуально, но дешевле
на порядки.

Также: `-stream_loop -1` у ffmpeg зависает намертво на этом хосте —
не использовать; видео = длина самого трека (удлинять трек на шаге 03,
а не зацикливать аудио/видео на шаге 04).

Кодирование: 1280x720, 5 fps (статичный кадр, высокий fps не нужен),
`-preset ultrafast` — иначе кодирование не укладывается в разумное
время на 1 vCPU.

## 3. Публикация на YouTube (шаг 05) — закрыто

Требовал Google Cloud OAuth2 client_id/secret + refresh_token с правом
`youtube.upload`. Владелец провёл разовый интерактивный consent-флоу в
браузере (создал Google Cloud проект, включил YouTube Data API v3,
Desktop OAuth client, прислал auth code). `pipeline/youtube_oauth.py
--check` подтверждает авторизацию, токен хранится в `.state/youtube_token.json`
(gitignored).

End-to-end прогон выполнен: взят готовый run `runs/20261002_023635/`
(idea.json/cover.png/track.mp3/video.mp4, 45с), `pipeline/05_publish.py`
реально опубликовал видео:
https://www.youtube.com/watch?v=Amn9z3lf5z8
(containsSyntheticMedia=True, selfDeclaredMadeForKids=False — выставлено
автоматически в теле запроса).

## 4. YouTube Analytics API (шаг 06) — известное ограничение

`pipeline/06_report.py` падает с `accessNotConfigured`: YouTube
Analytics API не включён в том же Google Cloud проекте (включена
только YouTube Data API v3 на шаге выше). Включение API в Cloud Console
— ещё один разовый ручной шаг для владельца (Library ->
"YouTube Analytics API" -> Enable), сам скрипт корректен и готов к
работе сразу после включения. Не блокирует MVP-критерии (публикация
видео — выполнена), оставлено как follow-up.
