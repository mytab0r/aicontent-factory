# DECISIONS — aicontent-factory

## 1. Источник музыки (MVP, шаг 03)

Контекст: нужен инструментальный lo-fi/ambient трек под видео, без
платных внешних SaaS (п.2 AGENTS.md) и без риска по лицензиям.

Проверено:
- 9router (`/v1/models`) — **нет** ни одной рабочей музыкальной/audio-gen
  модели (есть только text-chat и image). TTS-эндпоинт `/v1/audio/speech`
  формально существует в API-поверхности роутера, но реальных
  провайдеров под музыку/генерацию звука за ним не подключено.
- Suno/Udio — официального публичного API нет (см. открытый вопрос в
  PLAN.md), неофициальные обёртки — риск ToS/нестабильность, решили не
  трогать для MVP.
- CC0-треки как заглушка (вариант b) — отложили: добавляет ручной шаг
  (поиск/лицензионная проверка каждого трека), не масштабируется без
  участия человека.

**Выбор: вариант (a) — процедурная генерация локально**, чистый
numpy + stdlib `wave` (pipeline/03_music.py):
- случайные lo-fi минорные септаккордовые прогрессии (детерминированно
  по сиду = имя run-директории, чтобы прогон был воспроизводим);
- мягкая огибающая на аккордах + лёгкий low-pass (собственный
  однополюсный RC-фильтр) + статический "винил"-шум для тёплого
  звучания;
- полностью бесплатно, без лицензионных рисков, работает оффлайн.

Важная находка по среде: `scipy.signal.butter/lfilter` подвешивает
процесс насмерть на этом 1-vCPU хосте (threadpool deadlock) — поэтому
в `pipeline/03_music.py` **намеренно нет scipy**, только numpy.

ponytail: это не "настоящая" музыка с мелодией/ударными, а эмбиент-подложка.
Апгрейд, когда появится бюджет/нужда в качестве: подключить внешний
music-gen API (Suno/Udio/ElevenLabs Music и т.п.) за тем же интерфейсом
`generate_track()` — остальной пайплайн не изменится.

## 2. Сборка видео (шаг 04) — вшивание текстовой пометки

`ffmpeg -vf drawtext=...` на каждый кадр оказался неприемлемо медленным
на 1 vCPU (~0.13x realtime, т.е. 120s трек кодировался бы ~15+ минут).
Решение: надпись "AI-generated / synthetic content" печатается ОДИН РАЗ
в саму PNG-обложку через Pillow (`burn_overlay()`), а не per-frame
фильтром. Для статичного кадра результат идентичен визуально, но дешевле
на порядки.

Также: `-stream_loop -1` у ffmpeg зависает намертво на этом хосте —
не использовать; видео = длина самого трека (удлинять трек на шаге 03,
а не зацикливать аудио/видео на шаге 04).

Кодирование: 1280x720, 5 fps (статичный кадр, высокий fps не нужен),
`-preset ultrafast` — иначе кодирование не укладывается в разумное
время на 1 vCPU.

## 3. Публикация на YouTube (шаг 05) — закрыто

Требовал Google Cloud OAuth2 client_id/secret + refresh_token с правом
`youtube.upload`. Владелец провёл разовый интерактивный consent-флоу в
браузере (создал Google Cloud проект, включил YouTube Data API v3,
Desktop OAuth client, прислал auth code). `pipeline/youtube_oauth.py
--check` подтверждает авторизацию, токен хранится в `.state/youtube_token.json`
(gitignored).

End-to-end прогон выполнен: взят готовый run `runs/20261002_023635/`
(idea.json/cover.png/track.mp3/video.mp4, 45с), `pipeline/05_publish.py`
реально опубликовал видео:
https://www.youtube.com/watch?v=Amn9z3lf5z8
(containsSyntheticMedia=True, selfDeclaredMadeForKids=False — выставлено
автоматически в теле запроса).

## 4. YouTube Analytics API (шаг 06) — известное ограничение

`pipeline/06_report.py` падает с `accessNotConfigured`: YouTube
Analytics API не включён в том же Google Cloud проекте (включена
только YouTube Data API v3 на шаге выше). Включение API в Cloud Console
— ещё один разовый ручной шаг для владельца (Library ->
"YouTube Analytics API" -> Enable), сам скрипт корректен и готов к
работе сразу после включения. Не блокирует MVP-критерии (публикация
видео — выполнена), оставлено как follow-up.

## 5. Конкурентный анализ ниши и формула видео (после публикации MVP)

Запрошен владельцем после первого реального прогона (45с тестовый ролик).
Нельзя было сужать до одного жанра lofi — ACE-Step поддерживает любой
текстовый жанр-промпт, так что сравнивались все соседние "фоновая музыка
на бесконечном повторе" ниши, не только lofi.

Разобрано ~40 реальных каналов из нескольких соседних ниш (через
findachannel.net рейтинги + прямые YouTube-примеры):

| Ниша | Пример топ-канала | Видео | Подписчики | Оценка дохода/мес |
|---|---|---|---|---|
| Relaxing/nature music | Relaxing Nature In 4K | 463 | 1.09M | $5,087 |
| Easy listening | Dan Gibson's Solitudes | 1,750 | 127K | $2,910 |
| Meditation/relaxation | The Waters of Heaven | 551 | 216K | $1,263 |
| Sleep music | Healing Vibrations | 478 | 748K | $1,240 |
| Relaxing/nature music | Healing Soul | 72 | 255K | $1,369 |
| Sleep music | Music for Sleep | 167 | 144K | $827 |

Общие паттерны по всем нишам (не только lofi):
1. **Длительность — не 45 секунд ни у кого.** Доминируют два формата:
   короткие "сигнатурные" ролики 10-20 минут (для плейлист-логики/частых
   апдейтов) ИЛИ длинные looped-треки 1-12+ часов (sleep/study/focus —
   основной драйвер просмотров и удержания). Наш генератор ограничен
   разумной длиной одного API-вызова (ACE-Step практично до ~4 минут за
   вызов) — длинное видео нужно собирать конкатенацией нескольких
   сгенерированных треков в 04_assemble.py, не одним вызовом.
2. **Жанр — шире, чем "lofi".** Самые прибыльные каналы в выборке — не
   lofi hip-hop (это самая насыщенная поднниша, 2026: "everyone is making
   lo-fi"), а nature/relaxing ambient, easy listening, meditation/healing,
   sleep music. ACE-Step это умеет тем же `generate_track()` — просто
   другой текстовый промпт по жанру, пайплайн менять не нужно.
3. **Визуал — не статичная картинка.** Топ-каналы используют видео-фон
   (natural footage, медленный Ken Burns/зацикленное движение), не чистый
   статичный PNG. Наш 04_assemble.py пока даёт статичный кадр — это
   отставание от формата, не просто "другой стиль".
4. **Частота и возраст канала коррелируют сильнее жанра.** Каналы вроде
   Dan Gibson's Solitudes (с 2020, 1750 видео) явно выигрывают за счёт
   накопленного каталога, не разовых хитов — подтверждает стратегию
   "1 видео/день, не распыляться" уже в PLAN.md.

Решение:
- GENRE_PROMPTS (03_music.py) расширен за пределы lofi-зонтика: добавлены
  под-жанры из доходных соседних ниш (nature ambient, meditation/healing,
  easy-listening piano) — ротация шире, не привязана к одному поджанру.
- TRACK_DURATION_SEC дефолт поднят, плюс добавлен режим конкатенации
  нескольких сгенерированных кусков в один длинный трек/видео
  (LONG_FORM_MINUTES) для sleep/focus формата — обе длины (короткая
  "сигнатурная" и длинная looped) теперь доступны через один и тот же
  generate_track().
- Визуал (видео-фон вместо статичного PNG) остаётся ponytail: требует
  либо видео-gen API, либо сток-футажа с лицензией под коммерцию — не
  блокирует текущий MVP-критерий (сквозной рабочий прогон), следующий шаг.

## 6. Смена цели проекта: монетизация через мультиплатформенную дистрибуцию (2026-10-03)

Контекст: до этого момента пайплайн строился как "ядро" — один
long-form видео/день на один YouTube-канал. Владелец явно расширил
цель: **цель проекта = монетизация контента**, не просто публикация.
Поручено: добавить автоматизацию клипинга длинных видео в
шортсы/нарезки + интеграции с площадками, которые платят за
короткий контент (TikTok, YouTube Shorts, Instagram Reels и т.д.),
опираясь на реальный ресёрч бест-практис и готовые решения, а не
изобретать с нуля. Также явно разрешено добавлять
агентов/скиллы/плагины/скрипты/интеграции, если текущих не хватает
для "tiny team" масштаба проекта.

Статус: ресёрч запущен (4 параллельных потока) — (1) best practices
нарезки faceless lofi/ambient контента под шортсы, (2) официальные
ToS-compliant API постинга в TikTok/Shorts/Reels, (3) готовые
open-source инструменты клипинга под не-речевой (музыка/фон)
контент, (4) реалистичная экономика монетизации в этой нише
(payout/1000 просмотров, пороги входа, риск дублей контента по
YouTube spam-policy). Результаты и архитектурное решение — следующим
пунктом здесь после завершения ресёрча.

ponytail: пока НЕ трогаем прод-пайплайн (01-06) — это отдельный новый
модуль (07_clip.py / 08_distribute.py или аналог), подключаемый после
long-form публикации, не блокирующий существующий daily workflow.
